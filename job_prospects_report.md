### 1.2 High-Level Justification & Core Strengths
1. **Stateful Agentic Control (LangGraph StateGraph)**: Replaces fragile linear chains with a typed state machine (`GraphState`), dynamic RBAC SQL generation, regex fast-paths, and conditional routing nodes (`planner_node` -> `route_query` -> `sql_generator_node` / `semantic_node` -> `synthesizer_node`).
2. **Deterministic Guardrails & Date Normalization**: Injects real-time calendar reference dictionaries to eliminate relative date hallucinations (e.g., resolving "next Tuesday" or "Q3 renewal" into explicit ISO timestamps before SQL/entity generation).
3. **Multi-Model Economy-to-Review Escalation**: Implements a cost-conscious dual-tier LLM routing engine (Groq `llama-3.1-8b-instant` / `gpt-oss-20b` -> Gemini `gemini-2.5-flash` -> controlled fallback to `MANUAL_REVIEW_REQUIRED`) with real-time token telemetry and USD cost tracking in PostgreSQL (`ai_extraction_logs`).
4. **Hardened Multi-Tenancy & Relational Security**: Implements composite foreign keys `(user_id, organization_id)` at the database engine level, tenant mixins, anti-enumeration `HTTP 404` error responses, and constant-time CSRF double-submit token verification.
5. **Real-Time & Batch Voice AI Engineering**: Features a triple-engine ingestion pipeline: in-browser Web Speech API, real-time 16-bit 16kHz PCM streaming over WebSocket via `AudioWorkletNode` (`pcm-processor.js`) with Redis replay defense, and background asynchronous batch transcription with Faster-Whisper `large-v3-turbo` (int8 CPU execution), PyAnnote 3.1 speaker diarization, Silero VAD, and dynamic tenant client-name prompt injection.

### 3.1 Backend & Async API Architecture
* **High-Throughput Asynchronous Core**: Built on **FastAPI** utilizing async request lifecycles (`app/core/lifespan.py`, `app/main.py:35-48`) and **Psycopg 3** binary asynchronous driver (`app/database/session.py:23-34`), delivering low-latency non-blocking I/O.
* **Modular Router Organization**: Clean API separation across 12 distinct router modules under `app/api/v1/` with dual-mounting for auth and workspaces (`app/main.py:80-101`).
* **Starlette CSRF Protection Middleware**: Custom `CSRFProtectionMiddleware` implementing constant-time double-submit cookie verification (`secrets.compare_digest`) protecting state-changing HTTP methods (`POST`, `PUT`, `DELETE`, `PATCH`) (`app/core/csrf.py:63-102`).
* **Dependency Injection & Clean Layering**: Decoupled architecture using FastAPI's dependency injection (`get_db`, `get_current_principal`, `require_roles`, `get_notification_adapter`) enforcing strict separation between HTTP transport, domain services, and database repositories.

### 3.2 AI & Agentic Engine (LangGraph & Multi-Model Orchestration)
* **LangGraph Stateful StateGraph (`app/services/portfolio_copilot_service.py:277-290`)**:
  * **Typed Graph State**: `GraphState(TypedDict)` maintaining complete workflow execution context: `query`, `organization_id`, `user_id`, `role`, `route`, `sql_query`, `sql_error`, `db_result`, and `final_answer`.
  * **Graph Topology**: Defined with explicit nodes (`planner_node`, `sql_generator_node`, `semantic_node`, `synthesizer_node`) and conditional routing (`planner_node` -> `route_query` -> `sql_generator_node` or `semantic_node`), converging to `synthesizer_node` -> `END`.
  * **Fast-Path Regex Optimization**: High-performance regex checks (`_is_greeting`, `_meeting_schedule_date`, `_extract_client_lookup_name`, and `VECTOR_SEARCH_TERMS`) that bypass LLM invocation for deterministic queries, slashing latency from 1,200ms to <15ms (`app/services/portfolio_copilot_service.py:68-135`).
* **Dynamic RBAC SQL Generation**: The copilot dynamically constructs SQL queries with tenant boundaries physically injected into the prompt:
  ```python
  # Codebase Proof: app/services/portfolio_copilot_service.py:251-264
  # Ensures non-owner roles can only query their own client records
  user_filter = f"AND user_id = '{user_id}'" if role != "owner" else ""
  prompt = SQL_GENERATOR_PROMPT.format(
      organization_id=organization_id,
      user_filter=user_filter,
      schema=SCHEMA_CONTEXT,
      query=query
  )
  ```
* **Multi-Model Economy-to-Review Fallback Engine (`app/services/ai_routing_service.py:22-52`)**:
  * **Hinglish Preprocessing**: Automatic translation and normalization layer (`translate_transcript`) resolving multilingual Indian business terminology.
  * **Tier 1 (Economy)**: Groq `llama-3.1-8b-instant` / `gpt-oss-20b` for ultra-fast, low-cost extraction.
  * **Tier 2 (Review)**: Automated escalation to Gemini `gemini-2.5-flash` when extraction confidence is marginal or complex entity resolution is required.
  * **Tier 3 (Controlled Fallback)**: Graceful triage to `MeetingStatus.MANUAL_REVIEW_REQUIRED` without server crash or unhandled exceptions (`app/services/meeting_processing_service.py:92-102`).
  * **Real-Time Telemetry & Spend Audit**: Every LLM call records prompt version, latency in ms, prompt/completion tokens, calculated USD cost, and execution status to the `ai_extraction_logs` table (`app/services/ai_routing_service.py:75-101`).
* **Deterministic Guardrails & Date Normalization**: Injects real-time calendar reference dictionaries (current date, tomorrow, start of week, end of week, relative business quarters) directly into extraction prompts, eliminating relative date hallucinations (`app/ai/prompts.py:26-27`).
* **pgvector Hybrid Semantic Search**:
  * Embeddings generated using `BAAI/bge-m3` (1024-dimensional vectors) via `sentence-transformers` (`app/services/embedding_service.py:11-16`).
  * Hybrid cosine distance queries (`<=>`) combined with mandatory SQL `organization_id` and `user_id` filters (`app/services/semantic_search_service.py:29-55`).
  * Synthesizes rolling client summaries, pre-meeting briefs, talking points, and active risk signals (`app/services/memory_service.py:125-186`).

### 3.3 Multi-Tenancy & Data Layer
* **Pooled Multi-Tenant Relational Isolation**: Strict row-level isolation via `organization_id` and `user_id` columns across all 16 SQLAlchemy declarative models.
* **Composite Foreign Key Schema Integrity**:
  ```python
  # Codebase Proof: app/models/client.py:46-51, app/models/meeting.py:70-75
  __table_args__ = (
      ForeignKeyConstraint(
          ["user_id", "organization_id"],
          ["organization_memberships.user_id", "organization_memberships.organization_id"],
          name="fk_clients_membership",
          ondelete="CASCADE",
      ),
  )
  ```
  This guarantees that records cannot be orphaned or attached to users outside the specified tenant organization.
* **Anti-Enumeration 404 Defenses**: All repository lookups across tenant boundaries return `HTTP 404 Not Found` rather than `403 Forbidden`, preventing malicious actors from enumerating valid client or meeting IDs (`app/repositories/client_repository.py:29-38`).
* **Alembic Database Migrations**: 16 structured migration revisions (`alembic/versions/`) tracking complete schema evolution, foreign key additions, index creation, and data backfills.

### 3.4 Storage & Asset Lifecycle Management
* **MinIO S3-Compatible Object Store**: Centralized file and audio management (`app/services/minio_service.py`).
* **Tenant Hierarchical Namespacing**: Enforces object keys structured as `{organization_id}/{user_id}/{meeting_id}/{filename}` with path traversal sanitization (`app/services/minio_service.py:15-25, 48-58`).
* **Secure Presigned URLs**: Generates short-lived (3600s) presigned GET URLs issued only after authenticating user ownership in the database (`app/api/v1/routes_audio.py:171-206`).
* **Transactional Cleanup & Lifecycle**: Automatic cleanup of audio objects post-transcription when `PHILIXA_RETAIN_AUDIO=0` (`app/jobs/transcription_jobs.py:223-238`), with transactional rollback deleting MinIO objects if database commits or ARQ job enqueues fail (`app/api/v1/routes_audio.py:141-163`).

### 3.5 Voice AI & Real-Time Audio Engineering
* **Triple-Engine Ingestion Pipeline**:
  1. *Web Speech API* (`app/web/fast-dictation.js`): In-browser real-time dictation for low-latency text entry.
  2. *Live Streaming AudioWorklet WebSocket* (`app/web/pcm-processor.js`, `app/api/v1/routes_live.py`): Real-time 16-bit 16kHz PCM audio streaming via AudioWorklet (4096-sample buffer) over WebSocket with single-use ticket auth and Redis replay defense; supports Deepgram Cloud live streaming (`nova-2` Hindi/Hinglish) or Local Whisper buffer.
  3. *Asynchronous Background Processing* (`app/jobs/transcription_jobs.py`, `app/services/transcription_service.py`): Faster-Whisper `large-v3-turbo` (int8 CPU execution), FFmpeg audio normalization and bandpass filtering, Silero VAD filtering, PyAnnote 3.1 speaker diarization, and dynamic tenant-scoped client name prompt injection.
* **Dynamic Whisper Prompt Injection**: Injects tenant-specific client names into Faster-Whisper's initial prompt context:
  ```python
  # Codebase Proof: app/services/transcription_service.py
  # Drastically improves transcription accuracy for regional Indian names & domain terminology
  initial_prompt = f"Meeting discussing clients: {', '.join(tenant_client_names)}."
  ```
* **Conversational Voice Assistant Agent**: Full interactive voice loop (`app/services/voice_assistant.py`, `app/api/v1/routes_voice.py`, `app/web/philixa-voice.js`) combining intent extraction, memory context retrieval, short conversational synthesis, and low-latency TTS via Sarvam AI (`bulbul:v3`) or Deepgram Aura (`aura-asteria-en`).

### 3.6 Security, Cryptography & Auth Architecture
* **Password Cryptography**: Bcrypt with cost factor 12 (`app/core/security.py:14-17`, verified in `tests/unit/test_security_crypto.py:96-107`).
* **JWT Access & Refresh Architecture**: HS256 signed tokens with mandatory claims (`sub`, `sid`, `org_id`, `role`, `iat`, `exp`, `jti`, `type`), explicit rejection of `none` algorithm, and cookie security (`HttpOnly`, `SameSite=Lax`, configurable `Secure`) (`app/core/security.py:148-151`, `app/api/v1/routes_auth.py:74-114`).
* **Token Family Rotation & Replay Revocation**: User session tracking (`user_sessions` table) storing SHA-256 token hashes. If an already-rotated refresh token is replayed, the entire session family is instantly revoked (`app/api/v1/routes_auth.py:522-530`).
* **WebSocket Single-Use Ticket Replay Defense**: Short-lived (60s) tickets validated and marked in Redis (`philixa:ws_ticket_used:{jti}`) to prevent connection token reuse (`app/api/v1/routes_live.py:97-115`).
* **Production Guardrails**: Automated startup checks in `app/core/config.py:99-124` verifying minimum secret key entropy, disallowing CORS wildcards in production, and validating SMTP settings.

### 3.7 Production Hygiene & Automated Testing
* **Comprehensive Test Suite**: 14 automated test modules across unit, integration, and end-to-end customer journeys (`tests/conftest.py`, `tests/unit/`, `tests/integration/`, `tests/e2e/`).
* **Mock Fixture Architecture**: Includes `MockSMTPSink`, `MockRedisClient`, synchronous and asynchronous database engines, and parameterized multi-tenant test matrices (`tenant_matrix`).
* **Worker & Job Fault Tolerance**: ARQ worker separating transient network/DB retries (`Retry(defer=60)`) from permanent ML errors (graceful triage to `MANUAL_REVIEW_REQUIRED`) (`app/jobs/transcription_jobs.py:141-155, 206-221`).

### 8.3 Technical Interview Defense Strategies

#### Question 1: "Why did you choose LangGraph over traditional LangChain Chains or a simple OpenAI function-calling loop?"
* **Optimal Answer**:  
  *"Traditional LangChain Sequential Chains are linear DAGs that fail when an agent requires cyclic iteration, state persistence, or error correction. OpenAI function-calling loops lack structured state checkpointing. I chose **LangGraph** because it models the workflow as a formal state machine (`StateGraph`) using a typed schema (`GraphState`). This allowed me to implement:*
  *1. Dynamic conditional routing between SQL generation and vector search.*
  *2. Fast-path regex bypasses that save LLM costs on deterministic queries.*
  *3. Strict RBAC SQL prompt isolation based on tenant identity.*
  *4. Safe fallback transitions without breaking the conversation state.*

#### Question 2: "How do you guarantee tenant data isolation and prevent SQL injection or cross-tenant leakage in your Agentic Copilot?"
* **Optimal Answer**:  
  *"I enforced isolation across three distinct layers:*
  *1. **Database Schema**: All models enforce composite foreign keys `(user_id, organization_id)` tied to `organization_memberships`, making cross-tenant record association physically impossible.*
  *2. **Repository Layer**: All queries filter by `organization_id`, and non-owner roles automatically append `user_id` constraints. Unauthorized queries return `HTTP 404 Not Found` to prevent ID enumeration.*
  *3. **Agentic SQL Generator**: The copilot does not allow free-form unconstrained SQL. The prompt dynamically injects `organization_id` and role-based user filters directly into the system context. Furthermore, read-only transaction isolation prevents any state mutation via generated queries.*

#### Question 3: "Why did you use AudioWorklet for audio capture instead of standard MediaRecorder or containerized WebM audio?"
* **Optimal Answer**:  
  *"Standard `MediaRecorder` captures audio in compressed chunks (such as Opus/WebM) that require server-side demuxing and decoding before feeding into speech models, introducing significant latency and CPU overhead. By implementing a custom `AudioWorkletNode` (`pcm-processor.js`), audio is captured directly on the audio rendering thread as raw 16-bit 16kHz mono PCM buffers (4096 samples). This stream is piped over WebSockets directly into Deepgram or our Whisper buffer, reducing end-to-end voice latency to under 300ms while eliminating browser main-thread UI stutter.*
