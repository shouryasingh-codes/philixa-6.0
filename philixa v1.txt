Cost-control rules
One economy-model call first; expensive model only on escalation.
Never send full client history to a model by default.
RAG retrieves only 3–5 relevant evidence chunks.
Use local embeddings; cache by transcript-content hash.
Create embeddings once after finalized meeting, not every query.
ARQ jobs prevent request-time compute spikes.
Store audio only when enabled; keep transcript/evidence as needed.
Strict per-user monthly token/audio budget.
V1 Beta acceptance gates
PHILIXA V1 Beta is complete only if:

Pasted notes, uploaded audio, and live browser audio all work.
Invalid AI output never writes normal CRM data.
No invented due date is silently saved.
Client questions return source meeting/date evidence.
WhatsApp reminders are opt-in and duplicate-safe.
Audio/transcription/model failures are visible and recoverable.
Model cost is logged per meeting.
One pilot advisor can use it end-to-end for real meetings.

EXTRA FEATURES ADDED (BEYOND ORIGINAL SCOPE)
1. Global Voice AI Assistant (Philixa Brain): A floating action button (FAB) providing a Siri-like voice-in/voice-out global assistant using Deepgram for STT and Sarvam for TTS, capable of answering general chats, saving meetings, and querying clients on the fly.
2. Fast Dictation Mode (Tab 4): A 4th input tab added to bypass backend audio processing completely, utilizing the browser's native Web Speech API for zero-latency, real-time transcription.
3. Solo vs Meeting Live Modes: Added distinct UI buttons in Live Record to specifically separate 'Solo Record' (fast, no diarization) from 'Meeting Record' (slower, explicit speaker diarization for client conversations).
4. Client Auto-Identification & Resolution Popup: A smart Human-in-the-Loop (HITL) UI fallback. If the AI detects an ambiguous client name during extraction, it prompts the user with a modal to resolve the conflict instead of failing silently.
5. Hybrid AI Audio Routing (Strategy Pattern): An advanced backend architecture (`live_strategies.py`) that dynamically switches live audio processing between a local offline faster-whisper model and a high-speed cloud Deepgram API based on cost, speed, and privacy requirements.

NEW MAJOR FEATURE: PORTFOLIO COPILOT
6. Agentic Portfolio Copilot (Integrated AI Chat Assistant):
   A smart, conversational AI assistant integrated directly into the dashboard to help advisors query their portfolio data in natural language.

   Technology Stack Used:
   - LangGraph: Used for building the Agentic workflow with stateful routing (deciding whether a query needs SQL or Semantic Search).
   - LiteLLM: Used as the universal LLM router, allowing seamless connection to Groq's fast open-source models (e.g., `groq/openai/gpt-oss-20b`).
   - PostgreSQL (pgvector): Handles the complex unstructured data via embeddings and cosine distance (`<=>`) semantic search.
   - BAAI/bge-m3: The embedding model used for generating highly accurate vectors for meeting notes.
   
   What it can do:
   - Natural Language to SQL (Structured Data): You can ask "How many clients do I have?" or "Show me my upcoming commitments" and it will generate and execute safe SQL queries on the fly.
   - Semantic Vector Search (Unstructured Data): You can ask "Who was interested in a business loan?" and it will search through the embeddings of your past meeting notes to find the exact client and context.
   - AI Synthesizer: It doesn't just return raw database rows; it passes the data to an LLM synthesizer node that formats the output into a friendly, human-readable chat response.
   - Contextually Secure: It restricts all SQL and Vector queries to the currently logged-in organization, ensuring strict data privacy between users.

7. Team Performance Overview: 
   Added a dashboard table that aggregates clients, meetings, and commitments per employee (excluding organization owners) to give a clear view of team productivity.

8. Role-Based Access Control (RBAC) in Copilot: 
   Enforced strict data segregation at the AI layer. Regular employees can only query their own clients and meetings via Copilot, while owners can query data across the entire organization.

9. Employee Performance AI Queries: 
   Expanded the Copilot's SQL generation schema to include `users` and `organization_memberships` tables. Owners can now directly ask the AI questions like "Which employee has the most clients?" or "Show me Aman's performance", with explicit prompt rules preventing client-vs-employee hallucinations and raw markdown table dumps.
